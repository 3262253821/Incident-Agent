# 简历项目描述

## 一句话项目介绍

基于 LangGraph、FastAPI、Vue 3 和 MySQL 构建面向研发/运维的故障初步分析 Agent，复用 DevAtlas 版本化知识库的纯检索能力，完成日志分析、知识检索、服务状态查询、证据追踪和结构化报告闭环。

## 技术栈

```text
Python / FastAPI / LangChain / LangGraph / Pydantic
Vue 3 / TypeScript / Vite / Pinia / vue-router / Axios
MySQL / SQLAlchemy / Alembic / HTTPX
DeepSeek API / DevAtlas RAG API
```

## 简历要点

- 设计并实现 `agent → tools → observe → report` 的 LangGraph 工作流，支持单轮多工具调用、条件路由、最大模型请求次数和工具失败降级；
- 将日志分析、DevAtlas 知识库检索和服务状态查询抽象为统一 `ToolResult` 协议，使用 Pydantic 校验输入、外部响应和最终报告；
- 通过 `HttpRagGateway` 复用 DevAtlas `/search` 接口，保留 `document_id/version_id/chunk_index` 来源 metadata，避免将模型生成文本冒充真实引用；
- 使用独立 MySQL 保存 `agent_runs` 和 `agent_steps`，按用户 ID 隔离运行记录，并禁止持久化 JWT、API Key 和数据库密码；
- 使用 Vue 3 + TypeScript + Pinia + vue-router 实现登录态、故障输入、执行轨迹、观察结果、结构化报告和历史运行 Web Harness；
- 构建 MockRagGateway 和 FakeModel 测试体系，覆盖正常、未知服务、RAG 异常、非法报告、多工具和循环上限等路径。

## 面试追问回答

**为什么 DevAtlas 和 Incident Agent 分开？**

DevAtlas 是通用知识基础设施，负责文档生命周期、权限、向量化和检索；Incident Agent 是面向故障场景的应用，负责模型决策、工具编排、流程控制、证据组合和报告。两者通过纯检索接口连接，职责清晰且可以独立运行。

**为什么要保存 messages、observations、steps？**

`messages` 用于恢复模型上下文，`observations` 用于报告和业务判断，`steps` 用于调试、审计和前端展示。三者分别对应协议上下文、事实数据和执行轨迹，不能互相替代。

**如何控制模型幻觉和工具风险？**

工具白名单由 Python 注册，日志和文档只当作不可信数据；工具返回统一结果并保留错误码；报告只允许固定枚举字段，引用必须来自真实 metadata；Agent 只提供建议，不暴露生产执行工具。
