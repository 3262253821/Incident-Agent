## 5. 已知边界与"测不了"的部分（如实记录，不当成已完成）

1. **§17.2 案例 7「服务状态工具超时」在本项目里不可复现**：`get_service_status` 是进程内的 mock 注册表，没有网络与 I/O，因此不存在超时路径。真正会超时的外部工具只有 `search_knowledge`（`RAG_TIMEOUT`），本次用它覆盖案例 7 的**意图**（超时要被识别成超时，而不是通用失败）。要做真正的服务状态超时，需要先做 **P2-5 真实服务状态 provider**（仍未做）。
2. **真实模型返回 + 真实检索链路仍不是自动化依据**：§17.1 明确要求"真实模型不作为唯一的自动化测试依据"，本项目全部测试用 `FakeModel` / `MockRagGateway`；但**反向也成立**——自动化测试全绿不等于真实链路通过，真实 DeepSeek 返回 + 真实 `/search` 这条链路至今没有跑过（见交接文档 5.2 第 2 条）。
3. ~~**前端没有自动化测试**~~ → **已解决（2026-09-15：P1-5-3 建框架、P1-5-4 扩充到 97 条）**：引入 Vitest + `@vue/test-utils` + jsdom，`web/tests/` 下 **97 条**用例（11 个文件），`npm run test` 已进 CI 的前端 job。覆盖 store 状态机（含 `restore()` 的五种分支）、模态抽屉的 ESC/焦点陷阱/焦点归还、表单错误播报、`aria-live`、HTTP 客户端与响应拦截器（真实 axios 实例）、路由守卫与 `redirect` 过滤、入口装配，以及用 postcss 解析真实 `styles.css` 守住 `:focus-visible` 与 `prefers-reduced-motion`。**仍然没有**的是浏览器级端到端（真实点击、真实渲染引擎、真实导航、屏幕阅读器实际播报）——那是 **P2-6 Playwright**；jsdom 也不评估 `:focus-visible` 的匹配语义，本项只证明"规则与 DOM 属性正确"。
4. **`analyze_log` 的 `MAX_MATCHED_TEXT = 120`（单条命中文本截断）在当前正则下不可达**：四个模式最长只会匹配 11 个字符（`stack trace` / `异常堆栈` 等），因此无法构造"被截断"的用例。这是防御性代码，不是漏测——记录在此以免下次被误认为缺测试。
5. **CI 的真实运行结果已确认（2026-09-15，P1-4-5 完成）**：run `34930276951`（`head_sha=8eea1fb`）两个 job 全绿，后端含 `ruff` / `pytest` / `compileall` / `alembic heads`，前端含 `npm ci` / 类型检查与构建。确认它花的时间值得：第一次读结果就发现 CI 一直是红的，根因是"测试在无 `.env` 的检出里于收集阶段即失败"与"两条用例静默依赖开发机真实 MySQL"，另有我自己引入的一处 YAML 引号缺陷（表现为 **0 job 的失败运行**）。读取方式：`httpx.Client(trust_env=False)` 直连 `api.github.com`（走开发机代理会被共享 IP 的匿名配额限流）。
6. **`tests/test_ci_workflow.py` 不在设计文档的章节体系里**：它守的是 CI 定义文件本身（能解析、两个 job 与关键步骤仍在、backend job 提供 `INCIDENT_DATABASE_URL`）。放在这里是为了让"28 个文件 → 章节"的表不漏项，而不是把它算成设计文档要求。
7. **`tests/test_frontend_formatting.py` 也不在设计文档的章节体系里**：它守的是前端源码排版（P1-5-1）。与第 6 条同理，列进上表只是为了让"测试文件 → 章节"不漏项，不算设计文档要求；它的六条规则与"压缩/展开"合成样例（含 `@import url(...)` 里分号的误报修正）都写在该文件 docstring 里。
8. **`RunResponse.steps` / `observations` 的字段用"真实载荷"比对，而不是 schema 比对**（P1-5-2）：后端把它们存成 JSON dict（`list[dict[str, Any]]`，列就是 JSON），OpenAPI 只能描述成 `array<object>`，没有可比的属性表。`tests/test_api_type_contract.py` 因此跑一次真实 Graph、再经 `append_steps` 落库往返，用真实载荷锁定字段集合——这比 schema 比对更强，顺带证明 `POST /analyze` 与 `GET /runs/{id}` 返回的是同一个形状。
9. **测试规模口径以命令为准**：上表的条数是 2026-09-15 的实测值，新增测试后请重新跑 `py -m pytest tests --collect-only -q` 更新。
10. **CI 新增"前端必须跑单测"的门禁**（P1-5-3）：`tests/test_ci_workflow.py::test_frontend_job_runs_the_vitest_suite` 断言前端 job 里有 `npm run test` 且 `web/package.json` 是 `"test": "vitest run"`。理由是这一项引入的 50 条用例如果没进 CI，就只是"本地跑过"——与 P1-4-5 之前"CI 一直是红的却没人看"是同一类问题。**改 `ci.yml` 前后都要跑一次 `test_ci_workflow.py`**（YAML 解析失败会变成 0 job 的失败运行）。

> **假 adapter 的坑（P1-5-4 实测，写给下一个写前端 HTTP 测试的人）**：自定义 `adapter` 返回的响应**不会再经过 axios 内部的 `settle()`**（那是 adapter 自己的职责），所以一个 401 会被当成**成功响应**返回、拦截器根本不会触发——第一版 `apiClient.spec.ts` 就是这么全绿的假象。测试里必须自己按 axios 的规则抛 `AxiosError(message, code, config, request, response)`。这与交接文档第 9 节第 17 条（jsdom 陷阱）同类：**测试替身的语义边界本身就是一类 bug 来源**。
